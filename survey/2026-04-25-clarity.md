# CLARITY: A Framework and Benchmark for Conversational Language Ambiguity and Unanswerability in Interactive NL2SQL Systems (2026)

## Problem
Natural language to SQL (NL2SQL) systems are increasingly deployed in enterprise settings where users interact conversationally with databases. However, existing benchmarks assume clean, unambiguous queries — failing to capture the multi-faceted ambiguities and unanswerable questions that arise in real production interactions. As a result, even top-performing NL2SQL systems built on strong LLMs degrade severely when users ask ambiguous or underspecified questions.

## Method
**CLARITY** (arXiv: 2604.22313, April 25, 2026) introduces a framework for generating NL2SQL benchmarks that systematically incorporate multi-faceted ambiguities and diverse user behaviors in interactive, conversational settings. The framework is applied to the Spider and BIRD datasets — two standard NL2SQL benchmarks — augmenting them with queries that introduce schema-level ambiguities, unanswerable questions, and diverse user clarification behaviors. Leading NL2SQL systems using strong LLMs are tested under these conditions to measure performance degradation.

## Benchmarks / Datasets
- Applied to Spider and BIRD, two standard NL2SQL benchmarks
- Multi-faceted ambiguity types: schema-level, lexical, and structural
- Diverse user behaviors: clarification-seeking, assumption-making, and abandonment
- Interactive, multi-turn conversational evaluation setting
- First benchmark framework targeting conversational NL2SQL ambiguity and unanswerability

## Key Results

| Evaluation Dimension | Key Finding |
|---|---|
| Performance under ambiguity | Significant degradation in all leading NL2SQL systems |
| Ambiguity detection | Systems can detect ambiguous queries |
| Ambiguity localization | Systems struggle to pinpoint schema-level sources |
| Resolution accuracy | Systems fail to correctly resolve identified ambiguities |

- **State-of-the-art NL2SQL systems using strong LLMs suffer significant performance degradation under multi-faceted ambiguity — detecting ambiguity is not enough**
- Systems can identify that a query is ambiguous but cannot accurately localize or resolve the underlying schema-level source of ambiguity
- The gap between clean-query and ambiguous-query performance reveals that existing benchmarks mask critical fragilities in production NL2SQL deployment
- The CLARITY framework provides a systematic methodology for stress-testing conversational database interfaces before deployment

## FoxBrain Relevance
Foxconn uses enterprise databases for production data, supply chain records, and quality metrics. If FoxBrain or downstream NL2SQL tools are deployed to allow business users to query these systems in natural language, CLARITY's findings are directly applicable: ambiguous or underspecified queries — which are the norm in real business settings — will cause significant accuracy degradation. CLARITY provides a test framework for validating FoxBrain's database query interface before deployment, and highlights the need for explicit clarification-seeking behavior rather than silent assumption-making.
