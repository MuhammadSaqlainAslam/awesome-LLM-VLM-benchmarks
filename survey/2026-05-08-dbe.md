# DBE: Dynamic Boundary Evaluation — Beyond Fixed Benchmarks and Worst-Case Attacks (2026)

## Problem
Static benchmark evaluations suffer from two structural failure modes simultaneously: **ceiling effects** (frontier models saturate easy tasks, making differentiation impossible) and **floor effects** (worst-case adversarial attacks make all models appear equally poor). Both pathologies produce benchmark scores that fail to meaningfully rank models across the capability spectrum. A third failure mode — contamination from benchmark items appearing in training data — compounds both. No principled method existed to dynamically locate each model's true capability boundary and place it on a globally comparable difficulty scale.

## Method
**DBE** (Dynamic Boundary Evaluation; arXiv: 2605.06213, May 2026) introduces a calibrated item bank covering **four evaluation dimensions** — harmful request refusal, over-refusal prevention, constrained instruction following, and multi-turn sycophancy resistance — with difficulty labels validated across **9 reference language models**. The **Skill-Guided Boundary Search (SGBS)** algorithm actively locates each model's capability boundary using only API-level access, placing it on a globally comparable difficulty scale without requiring model internals. The method eliminates saturation effects while remaining compatible with existing datasets.

## Benchmarks / Datasets
- Calibrated item bank: 4 dimensions (harmful refusal / over-refusal / constraint following / sycophancy resistance)
- Difficulty labels validated across 9 reference language models
- SGBS algorithm: API-level access only (no logits / model internals required)
- Compatible with existing evaluation datasets
- Saturation-resistant by design

## Key Results

| Property | Standard Benchmark | DBE |
|---|---|---|
| Ceiling effects | Present (frontier models saturate) | Eliminated |
| Floor effects | Present (worst-case attacks) | Eliminated |
| Model differentiation at top | Poor | Meaningful |
| Model differentiation at bottom | Poor | Meaningful |
| Required access | Internal weights helpful | API-only sufficient |

- **DBE eliminates both ceiling and floor effects simultaneously — frontier models that appear identical on standard benchmarks are meaningfully differentiated on their actual capability boundary**
- SGBS boundary search requires only API-level access — applicable to any commercial model without special access or logit exposure
- Four-dimension design covers safety, over-safety, instruction compliance, and behavioural consistency — more comprehensive than single-domain safety benchmarks
- Compatibility with existing datasets means DBE can augment rather than replace current evaluation infrastructure

## Enterprise / Industry Relevance
Foxconn's FoxBrain model selection and monitoring face the exact failure modes DBE addresses. When comparing frontier models for FoxBrain deployment, standard benchmark scores show near-identical performance because models are at saturation — DBE's boundary-finding approach would reveal meaningful performance differences even among frontier-tier models. For FoxBrain's sycophancy resistance dimension (critical for supplier negotiation or quality assessment scenarios where the model must resist agreeing with incorrect user assertions), standard benchmarks produce floor effects that make all models appear equally poor — DBE locates the actual boundary where each model begins failing, enabling principled selection. The API-only SGBS algorithm is immediately applicable to FoxBrain's model evaluation pipeline without requiring model weight access, making it a practical tool for ongoing capability monitoring as model versions are updated.
