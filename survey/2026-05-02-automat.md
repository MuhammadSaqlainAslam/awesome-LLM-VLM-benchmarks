# AutoMat: Can Coding Agents Reproduce Findings in Computational Materials Science? (2026)

## Problem
AI coding agents are increasingly proposed for scientific research automation, but their real-world capability is evaluated on generic software engineering benchmarks (SWE-Bench, HumanEval) that do not require domain expertise. Computational materials science represents a critical test: reproducing published findings requires not just code generation but understanding simulation methodologies, interpreting domain-specific outputs, and validating results against established physical constraints. No benchmark had tested whether coding agents can execute the complete end-to-end workflow of a domain-expert scientific publication.

## Method
**AutoMat** (arXiv: 2605.00803, May 2026) is a benchmark curated with materials science domain experts containing real claims from published computational materials science papers. Each task requires an agent to recover and execute the complete end-to-end computational workflow needed to support or refute the paper's claim — including code generation, simulation setup, execution, and result interpretation. Multiple representative coding agent configurations across several foundation models are evaluated. Primary failure modes are systematically categorised: incomplete procedures, methodological deviations, and execution fragility.

## Benchmarks / Datasets
- Real published claims from computational materials science papers
- Expert-curated with materials science domain specialists
- End-to-end workflow evaluation (code generation → simulation → result interpretation)
- Multiple coding agent configurations and foundation models
- Failure mode analysis: incomplete procedures / methodological deviations / execution fragility

## Key Results

| Metric | Result |
|---|---|
| Best-performing agent success rate | 54.1% |
| Worst failure condition | Workflow reconstruction from paper text alone |
| Primary failure mode 1 | Incomplete procedures |
| Primary failure mode 2 | Methodological deviations |
| Primary failure mode 3 | Execution fragility (environment brittleness) |

- **Best-performing coding agent achieves only 54.1% success rate on reproducing computational materials science findings — even the strongest agents fail on nearly half of expert-validated scientific tasks**
- Agents perform worst when workflows must be reconstructed from paper text descriptions alone (without provided code) — the gap between code comprehension and scientific workflow generation is severe
- Three systematic failure modes: (1) procedures left incomplete mid-execution, (2) methods that deviate from the paper's described approach, (3) execution failures due to environment brittleness
- Generalisation from generic coding benchmarks (SWE-Bench) to domain-specific scientific reproduction is poor — SWE-Bench performance does not predict AutoMat success

## Enterprise / Industry Relevance
Foxconn's R&D and materials engineering teams increasingly explore AI assistance for computational simulation of manufacturing materials (semiconductor substrates, structural components, thermal interfaces). AutoMat's 54.1% ceiling even for the best agents means that FoxBrain's use in computational materials workflows must be treated as a collaborative tool requiring expert validation, not an autonomous agent. The specific failure mode of "workflow reconstruction from text" is critical for Foxconn's IP security: FoxBrain attempting to generate computational workflows from internal engineering specifications will face the same reliability ceiling as AutoMat agents working from paper descriptions. More broadly, AutoMat's methodology — building a domain-expert-curated reproduction benchmark — provides a direct template for Foxconn to create its own FoxBrain capability audit: curating internal engineering calculation cases with known correct results to measure FoxBrain's actual capability ceiling in Foxconn-specific domains.
