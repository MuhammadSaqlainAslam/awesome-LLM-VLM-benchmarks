# BLAST: Benchmarking LLMs with ASP-based Structured Testing (2026)

## Problem
Answer Set Programming (ASP) is a powerful declarative programming paradigm widely used for combinatorial optimization, knowledge representation, and constraint satisfaction — yet it has been almost entirely absent from LLM code generation benchmarks. Existing code generation evaluations focus on imperative languages (Python, Java, C++) and cannot measure LLM capability on declarative logic programming, leaving a major blind spot for applications requiring structured, verifiable reasoning.

## Method
**BLAST** (arXiv: 2604.22306, April 25, 2026) is the first benchmarking framework for evaluating how well large language models can generate Answer Set Programming (ASP) code. The framework introduces two novel semantic metrics tailored specifically for ASP code generation — addressing the fact that standard syntax-based metrics are insufficient for declarative code where semantic equivalence matters more than textual similarity. BLAST is evaluated on ten graph-related problems drawn from the ASP literature, testing eight state-of-the-art LLMs.

## Benchmarks / Datasets
- Ten graph-related problems from the ASP literature
- Two novel semantic metrics designed specifically for ASP code generation
- Eight state-of-the-art LLMs evaluated
- Focus on declarative programming paradigm (Answer Set Programming)
- First benchmark specifically targeting LLM performance on ASP code generation

## Key Results

| Evaluation Dimension | Key Finding |
|---|---|
| ASP code generation overall | Significant variation across the 8 models tested |
| Semantic metric design | Standard syntax metrics insufficient for declarative code |
| Problem complexity | Performance degrades on more complex graph constraint tasks |
| Frontier vs. smaller models | Notable performance gap on ASP-specific constructs |

- **BLAST establishes the first structured evaluation framework for LLM performance on Answer Set Programming — a previously under-explored area critical for constraint-based reasoning applications**
- Standard code generation metrics are insufficient for ASP; semantic correctness (whether the program produces correct answer sets) requires purpose-built evaluation
- Significant variation across the 8 tested LLMs indicates ASP is a differentiated capability, not uniformly captured by general reasoning benchmarks
- The benchmark reveals that LLM competence on imperative code generation does not automatically transfer to declarative ASP programming

## FoxBrain Relevance
Answer Set Programming and declarative constraint solving are relevant to Foxconn's production scheduling, capacity planning, and constraint optimization problems — areas where formal logic-based reasoning is more reliable than neural heuristics. If FoxBrain is used to assist engineers in writing ASP or constraint programming code for production optimization, BLAST provides the evaluation framework for measuring that capability. More broadly, BLAST's finding that declarative programming is a distinct, weakly-evaluated capability signals that FoxBrain's code generation competence must be validated specifically on the programming paradigms used in Foxconn's technical stack, not inferred from general benchmarks.
